## 它是什么

Quicker 是一个常驻在 Windows 任务栏的小工具。**按一下鼠标中键**,屏幕边缘会弹出一个"动作轮盘",里面是你提前录好的动作(模拟按键、运行脚本、打开应用、填入文本片段……)。

最直观的功能类比是 AutoHotkey + 一个图形化面板 + 一个动作市场。

核心特点:

- **图形化面板**,不用写配置文件就能配出几百个动作
- **动作市场**可以直接装别人做好的动作(键鼠模拟、窗口管理、文本处理、OCR、翻译……)
- 支持 **组合动作**(一个按钮里串多个步骤,带条件分支)
- 内置 **文本面板**(类似 aText / Espanso 的 snippet 工具)
- 完全本地运行,免费版够用

## 我用 Quicker 解决了哪些事

嵌入式开发日常里有大量重复操作:打开串口助手、查手册页、烧录、写测试日志、复位、读寄存器…… 这些动作每个 3 秒,加起来一天浪费半小时很正常。Quicker 把它们压成一个按钮。

下面是我**每天都在用**的动作举例,分两类:

### 1. 系统级 / 跨软件

| 动作 | 触发 | 干什么 |
|------|------|--------|
| 截屏 + OCR | 中键 + 1 | 截屏后自动 OCR 文字到剪贴板,贴到 Claude Code 里直接问 |
| 搜当前窗口 | 中键 + 2 | 把当前窗口标题 + 选中文本塞进浏览器搜索框 |
| 打开 Keil 工程 | 中键 + 3 | 跑一段脚本定位最近修改的 `.uvprojx` 并打开 |
| 复制文件路径 | 中键 + 4 | 把资源管理器当前选中文件的绝对路径复制到剪贴板 |
| 重启串口助手 | 中键 + 5 | 关掉所有 `PuTTY` / `Xshell` 进程再开一份 |

### 2. 嵌入式专用

| 动作 | 触发 | 干什么 |
|------|------|--------|
| 烧录 STM32 | 中键 + Q | 调用 `STM32_Programmer_CLI` 一键烧录 |
| 读 J-Link SN | 中键 + W | 命令行查 J-Link 序列号,贴到 bug 报告 |
| 复位目标板 | 中键 + E | 触发 NRST 引脚或者发个串口指令 |
| 串口日志打时间戳 | 中键 + R | 给剪贴板里的日志每行加 `[HH:MM:SS]` 前缀 |
| 查芯片手册 | 中键 + T | 把当前选中的寄存器名塞进百度 / Google |

每一项在 Quicker 里只需要 **30 秒配置一次**,之后每天省 5–10 秒,一年就是好几小时。

## 怎么配出"嵌入式专用动作"

举一个完整的例子:**烧录 STM32 + 打开串口**。

1. 中键调出轮盘 → 右键 → "新建组合动作"
2. 加两个步骤:
   - **步骤 1**:运行程序 → `C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeProgrammer\bin\STM32_Programmer_CLI.exe -c port=SWD -d "C:\firmware\project.bin" 0x08000000 -v -rst`
   - **步骤 2**:启动应用 → `Xshell.exe -newtab "192.168.1.10:23"`
3. 设触发键:中键 + Q
4. 保存

以后按住鼠标中键往 Q 上一甩,就完成"烧录 + 开串口"两件事。

> 提示:Quick 步骤之间默认串行,可以加 `等待窗口` / `条件判断` / `正则提取输出` 来做更复杂的流程。我自己写过一个"烧录 → 等 5 秒 → 抓串口前 200 行 → 自动贴到 Claude Code 提问"的组合,调试协议 bug 时特别好用。

## 跟 Claude Code 配合

这是我最推荐的搭配:

1. **截屏 + OCR 一键提问**:截一段串口报错 → OCR → 自动 `type` 到 Claude Code 当前输入框 → 回车。整个流程 1.5 秒,等于"看到错就问"。
2. **报错日志预处理**:Quick 动作里跑一段 Python,把 `0x1234 -> 0x5678` 这种寄存器错配格式化成可读的 diff,再喂给 Claude。
3. **快捷改代码片段**:在文本面板里放好嵌入式常用的模板(`__WEAK` 函数、`HAL_UART_RxCpltCallback`、DMA 双缓冲……),Quicker 里搜一下就贴出来。

## 优缺点

**适合用的人**:
- 每天和 Windows / IDE / 串口助手打交道
- 重复操作多(烧录 / 复位 / 抓 log / 查手册)
- 不想花时间学 AutoHotkey 但想要自动化

**不适合的场景**:
- 纯 Linux / macOS 用户(没用)
- 一天就点两三次鼠标(没必要)
- 公司电脑不让装第三方常驻服务(找 IT 谈)

**坑**:
- 免费版限制 5 个动作组合,**专业版 99 元/年**很值
- 部分动作要管理员权限,公司电脑要先申请
- 截屏 OCR 用的是本地引擎,准确率没有云端 API 高(但胜在快 + 离线)

---

## 我的设置建议

如果你刚开始用,**别一口气配 50 个动作**。先从 3 个最痛的开始:

1. 一个**当前时间戳**动作(写日志必备)
2. 一个**OCR + 提问**动作(配合 Claude Code)
3. 一个**你最常用的脚本启动**(我的是烧录)

用一周觉得离不开,再慢慢加。动作太多反而记不住,得不**等于没用**。

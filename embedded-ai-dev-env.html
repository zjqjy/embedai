嵌入式 AI 开发环境 · 四层工作流

如果你是用 Keil + CubeMX 入门的嵌入式工程师,或者还在百度 + CSDN 拼凑代码的学生 —— 这篇文章把你现在用的工具重新摆一遍位置。四层各司其职,外加一个管 AI 订阅的后勤。

↓ 本期工具下载链接在文末
// 01 回忆

你最早是怎么学的嵌入式?

CubeMX 配引脚 → Keil 写代码 → 编译下载。学生时代一个工程一个工程地练,学会了外设、看时序。

做项目遇到问题 → 百度 / CSDN 搜一段,复制进去试。拼拼凑凑也能解决。

这两种方式有问题吗?没有。AI Agent 出现之前,这是嵌入式开发者最主流的路。

但今天 —— 工具的角色变了。

// 02 四层结构

这套环境的四层结构

按工作流拆成四层,外加一个后勤:

L1 写代码      VSCode + Claude Code + EM-SKILL
L2 版本控制    Git
L3 基础框架    STM32CubeMX
L4 编译交付    MDK5 Keil
后   勤        ccswitch (四层之外)
L1
写代码
创作中心
VSVSCode CClaude Code EMEM-SKILL
只管写,不管编译 —— AI 结对写码,闭环不离开编辑器。
L2
版本控制
后悔药
GGit
每写完一个模块就 commit —— 给 AI 留演进上下文。
L3
基础框架
出骨骼
MXSTM32CubeMX
配时钟、配外设、生成 HAL —— 血肉都长在骨骼上。
L4
编译交付
最后一棒
µVMDK5 Keil
退居后台出工具链 —— 疑难时做断点、看寄存器。
后
后勤 · 四层之外
SUPPORT
ccccswitch
统一管 Claude Code / Codex / Gemini CLI 订阅与渠道切换,顺带管 MCP / Token。
// 03 总结

一句话

VSCode + Claude Code + EM-SKILL 写代码,Git 管版本,CubeMX 出骨骼,Keil 管编译交付,ccswitch 盯 AI 订阅。 → 而你,只负责架构设计和审查。
